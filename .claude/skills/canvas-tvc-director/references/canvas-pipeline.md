# 画布落地手册：把 TVC 导演流程搭成节点工作流

> **职责**：SKILL.md 讲「拍什么、怎么写」，本文件讲「在画布上怎么搭、怎么跑、怎么验」。
> 所有工具名均为画布 MCP 工具（`mcp__canvas__*`），每次调用都要带 `canvasId`。

---

## 一、画布的几个硬事实（先记住，后面全靠它）

| 事实 | 对 TVC 流程的意义 |
|------|------------------|
| 提示词写在生成节点自己的 `prompt` 上；**连线只传参考素材** | 一张图/一段视频 = 一个节点；提示词改了直接 `update_node` |
| 生成节点的参考素材**按入边顺序编号**为图1、图2、图3… | 提示词里的 `图1/图2` 必须与连线先后严格一致——**先连谁谁是图1** |
| `image_gen` 只收图片；`video_gen` 收图片 / 视频 / 音频；`video_concat` 只收视频、入边顺序 = 成片顺序 | 拓扑按「上传 → 资产 → 分镜 → 视频 → 拼接」从左到右 |
| 超出模型参考上限的素材**提交时被丢掉**（不报错） | 连线前对照 `list_media_models` 的 `maxReferenceImages` |
| 生成是异步的：触发立即返回 `generationId`，用 `wait_for_generations` 等（单次 ≤25 秒，没完再调） | 每个阶段：触发 → 等 → 自审 → 给用户看 |
| 下游可以在上游还在排队/生成时触发（会等上游出结果）；上游**从没触发过**则下游报错 | MCP 下逐个调用，先触发上游再触发下游 |
| 同一节点再次 `generate_media_node` = 出一个新版本 | 迭代时改 prompt 后对**原节点**重跑，不要删了重建 |
| `get_canvas` 的 `media` 给出每个节点最新版本的 `status` 与公网 `url` | 可以把产物下载下来**亲眼看**（见第五节） |
| 用户能在浏览器里实时看到画布 | 开始改一块画布前先在预览里打开 `canvasUrl`（MCP 服务的约定） |

## 二、标准拓扑（30 秒 · 品牌世界穿梭型为例）

```
列0 上传            列1 资产                  列2 分镜/定格                         列3 视频                          列4 成片
x=40               x=360                    x=680                                x=1000                           x=1320

① 产品参考图 ──────▶ ② 产品多视图 ──┬────────▶ G1 · 0-15s · 3x3 ──(图1)──────▶ S1 · 0-15s ──────────────▶ ⑩ 成片 30s
 (image_upload)      (image_gen)    │   (图1)  (image_gen)                    ▲(图2 = ②)                    (video_concat)
                                    │                                         │                                ▲
                     ③ 模特造型图 ───┼──(图2)─▶ G2 · 15-30s · 3x3 ──(图1)──────▶ S2 · 15-30s ─────────────────┘
                     (按需)          │                                         ▲(图2 = ②, 图3 = EF)
                     ④ 场景图 ×N ────┘──(图3)                                  │
                     (按需)          └──────────▶ EF · End Frame ──────────────┘
```

**每个节点的入边（按这个顺序连，决定图几）**：

| 节点 | 类型 | 入边顺序 → 提示词里的编号 |
|------|------|------------------------|
| ① 产品参考图 | `image_upload` | 无（素材来源见第四节） |
| ② 产品多视图 | `image_gen` | ①（图1） |
| ③ 模特造型图 | `image_gen` | ②（图1，穿戴/手持类产品必连）→ 模特参考照片（图2，如有） |
| ④ 场景图 | `image_gen` | 场景参考照片（图1，如有）；无参考则无入边，纯文生图 |
| G1…Gn 多宫格分镜 | `image_gen` | ②（图1）→ ③（图2，如有）→ 本段用到的 ④（图3…） |
| EF End Frame | `image_gen` | ②（图1） |
| S1…Sn 段视频 | `video_gen` | 本段 Gk（图1）→ ②（图2）→ **最后一段额外连 EF（图3）** |
| ⑩ 成片 | `video_concat` | S1 → S2 → … 按时间顺序 |

**时长 → 规模**：15s = 1 张分镜 + 1 段视频；30s = 2 + 2；60s = 4 + 4。每段视频 15 秒，与一张 3x3 分镜一一对应。15s 的片子只有一段视频，不需要拼接节点（成片就是 S1）。

**布局**：按上面的列从左到右，列间距 320px；同列纵向错开，16:9 卡片行距 ≥260px（建议 300），9:16 卡片行距 ≥498px（建议 540）。具体起点以 `get_canvas` 返回的「放置安全区」为准，画布非空时整体放进安全区。

**标签（label）**：带序号 + 职责 + 时段，让用户在画布上一眼看懂，例如
`② 产品多视图 · 锁外观`、`G1 · 0-15s · 品牌世界 · 产品 7/9`、`S2 · 15-30s · 产品世界`、`EF · End Frame · 留白放 Logo`、`⑩ 成片 · 30s`。

**建节点**：一次 `add_nodes` 建完一个阶段的全部节点（建生成节点时就把 `prompt` / `model` / `params` 带上），再逐条 `connect_nodes`（**逐条调用、等上一条返回再连下一条**——顺序就是图号）。

## 三、模型与档位

开工前调一次 `list_media_models`（image 和 video 各一次），按下表选；目录里没有首选模型时，按「选型条件」挑能满足的。

| 用途 | 首选 | 档位 | 选型条件（首选不可用时） |
|------|------|------|----------------------|
| 产品多视图 / 模特造型 / 场景图 | `nano-banana-pro` | `aspect_ratio` 跟随成片画幅（多视图、造型图用 16:9 横排更清楚），`resolution: "2K"` | 收 ≥3 张参考图、复杂构图强 |
| 多宫格分镜 Gk | `nano-banana-pro` | `aspect_ratio` = **成片画幅**，`resolution: "4K"` | 同上；分辨率越高，每格细节越能撑住视频参考 |
| End Frame | `nano-banana-pro` | `aspect_ratio` = 成片画幅，`resolution: "2K"` | 同上 |
| 段视频 Sk | `seedance-2` | `aspect_ratio` = 成片画幅，`resolution: "1080p"`，`duration: "15"`，`with_audio: "true"` | 参考图走 reference（**不能**是只吃首帧的模型，如 `seedance-1.5-pro`）、收 ≥3 张参考图、支持 15 秒；备选 `seedance-2.5`（参考多、最长 30 秒） |

- **为什么 3x3 分镜的画幅等于成片画幅**：一张 16:9 的图切成 3x3，每格恰好也是 16:9；9:16 同理。格子比例与成片一致，视频模型照着格子构图时不用二次裁切。所以竖屏片也用 3x3（不要用上游知识库里竖版推荐的 2x3）。
- **`with_audio: "true"` + 提示词写「无背景音乐」**：保留环境音效（风声、水声、机械声），禁止模型自带 BGM——各段 BGM 在拼接处会断裂，配乐留给后期统一铺。用户明确要静音就设 `"false"`。
- **提示词长度**：首选模型的上限足够长；换成上限小的备选模型（如某些模型只有 1500–2500 字）时，先压缩逐 Phase 描述再提交。
- 参数只能传 `values` 里的原值（注意有的模型画幅写 `16x9`）；不合法时 `add_node` 返回 `invalid_params` 与 `issues`，按 issues 修正。

## 四、外部素材上画布（产品参考图、模特照、场景参考）

| 用户给的是 | 做法 |
|-----------|------|
| 公网 https 链接（电商图、官网图） | `import_asset(url)` → 返回 `versionId` 与 `uploadNodeType` → `add_node(type=image_upload, versionId=…)` |
| 本地文件 / 聊天里的图片 | MCP 拿不到本地文件：建一个**空的** `image_upload` 节点，label 写清「① 产品参考图 · 请在此卡片上传」，请用户在画布卡片上上传；用户说传好了再 `get_canvas` 确认该节点 `status=done` |
| 已在画布上的素材 | 直接复用该节点，不重复导入 |

素材到位后，**下载下来亲眼看一遍**（见第五节），据此写「产品标准描述」——这是画布版相对上游的最大优势：不必猜产品长什么样。

## 五、自审：每个阶段出图后先自己看

生成完成后 `get_canvas` 的 `media[].url` 是公网地址。下载到会话 scratchpad 再用 Read 查看：

```bash
curl -sSL -o "<scratchpad>/tvc/G1.jpg" "<media url>"
```

视频可用 ffmpeg 抽帧再看（本机没有 ffmpeg 就跳过，只看分镜与 End Frame）：

```bash
ffmpeg -loglevel error -i "<scratchpad>/tvc/S1.mp4" -vf "fps=1/3" "<scratchpad>/tvc/S1_%02d.jpg"
```

**各阶段自审清单**（不过关就按 SKILL.md 的审片原则改 prompt 重跑，再给用户看）：

| 阶段 | 看什么 |
|------|-------|
| 产品多视图 | 外观、配色、Logo 位置、比例与参考图一致；视角齐全（3/4、正、侧、背 + 2-3 个细节微距）；白底、光向统一 |
| 模特造型 / 场景 | 造型全身、服装款式颜色明确；穿戴类产品在每个视角都在身上；场景无人无产品、时间天气明确 |
| 多宫格分镜 | 确实是 3x3 九格、格序清楚；产品出镜格数与规划表一致（≥70%、单张无产品格 ≤2、无连续 3 格无产品）；产品外观跨格一致；每格景别/视角/光向符合描述；最后一张分镜的末格与 End Frame 构图呼应 |
| End Frame | 产品居中或偏置、背景干净、Logo / Slogan 留白位置明确；画面里没有乱码文字 |
| 段视频（抽帧） | 是全屏连续画面而不是宫格分屏；产品外观没漂移；节奏与 Phase 时间大致对应；没有字幕/水印 |

## 六、触发与等待（MCP 下的节奏）

1. 一个阶段的节点建好、连好、prompt 写好后，**按依赖从上游到下游**逐个 `generate_media_node`（同层节点之间无依赖，可连续触发）。
2. 收集返回的 `generationId`，用 `wait_for_generations`（最多 20 个 id、单次 ≤25 秒）循环等，`done=false` 就再调；**不要重复触发同一节点**。
3. 某个节点 `failed`：从 `get_canvas` 的 `media[].error` 读原因——参数/敏感词问题改 prompt 或档位，再对**该节点**重跑。
4. 画布返回 `CANVAS_BUSY`（用户或画布内置 agent 正在改）：稍等再试，不要换别的画布。
5. 视频段与拼接：所有 Sk 触发后，即可触发 `merge_video_node`（它会等上游视频都出结果再拼）；触发前核对返回的 `order` 与叙事顺序一致，不一致传 `order` 纠正。

## 七、迭代（审片阶段）

- **改一个节点**：`update_node` 改 prompt（必要时 `set_node_model` 改档位）→ 对同一节点 `generate_media_node`。下游已经用过旧版本的，需要按依赖重跑下游（例：改了 G1 → 重跑 S1 → 重拼成片）。
- **单变量**：一次只改一个维度，告诉用户这次改了什么、预期变化是什么。
- **不要**「建一批再全删重做」；推倒重来用 `clear_canvas`（破坏性、不可撤销，先征得用户同意）。
- 多次（>3 次）微调无效：退一步看根因——常见是参考图编号错位（连线顺序 ≠ 提示词图号）、参考超出模型上限被丢、或产品在 prompt 里的位置权重太靠后。

---

## 八、画布做不到的事（不要承诺）

- 加字幕、Logo、Slogan、转场特效、配乐混音——这些是后期。画布只能靠提示词影响画面，用 `video_concat` 硬切拼接。End Frame 只负责**留白**。
- 读取用户本地文件、上网找素材——素材只能来自 `import_asset` 的公网链接或用户在卡片上传。
- 模型目录之外的模型与档位。
