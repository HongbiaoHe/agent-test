# create-skills · 给 Spark 写技能

技能是一份**可复用的工作流说明书**（SKILL.md）。保存后，用户在对话里输入 `/技能名 需求` 就能让你照着它做；任务与技能说明相符时，你也会自己读它来用。

## 你在写给谁看

技能的读者是**将来的你自己**——同一个 Spark agent，拿到的工具与限制完全一样：
- 文件工具（ls / read_file / write_file / edit_file / glob / grep）只能访问当前会话的工作区；
- execute 在用户电脑上跑命令，单条最长 120 秒，不能 sudo、不能全局安装软件；
- 会话的权限档位可能是只读（不能写文件、不能执行命令）、询问（每次写和执行都要用户批准）或自动；
- 能用用户已连接的 MCP 连接器工具；能用 ask_user 向用户提问。

只写这些能力**真的做得到**的步骤；做不到的事（例如访问用户没连接的服务）不要写进技能。

## 流程

1. **弄清目标**（缺什么问什么，一次问完，用 `ask_user`；用户已经说清楚的不要再问）：
   - 这个技能解决什么任务？用户以后会怎么说出这个需求（触发说法）？
   - 每次运行需要用户提供哪些输入？哪些可以有默认值？
   - 产出是什么：文件（放在工作区哪里、什么格式）、一段回复、还是对外操作？
   - 如果用户是想把**本次对话里刚做过的流程**存成技能，直接从对话里提炼，少问。
2. **起名与写说明**：
   - `name`：小写字母、数字、连字符，≤64 字符，例如 `weekly-report`。不能用内置技能的名字（如 `create-skills`）。
   - `description`：一段话写清**做什么 + 什么时候用**，把用户可能的说法写进去（它决定你以后能不能认出该用这个技能）。≤1024 字符。
3. **写正文**（Markdown，不含 frontmatter，save_skill 会替你加上），至少包含：
   - **输入**：要向用户收集什么、缺了怎么补默认值。
   - **步骤**：按顺序写清每一步用哪个工具做什么，产物放在工作区的哪里。
   - **模板 / 写法**：产出的结构、格式与示例，写具体（"标题 + 3 条要点 + 风险"），不写空话（"写得专业"）。
   - **检查清单**：交付前要核对的点。
   - 篇幅够用就好，通常 40–200 行；不要重复 agent 已经知道的通用规则。
4. **附带文件（可选）**：内容长的模板、参考资料放 `references/xxx.md`，可执行的辅助脚本放 `scripts/xxx.py`（或 .sh / .js），在正文里写清什么时候读、怎么运行（如 `python3 <技能目录>/scripts/xxx.py`）。脚本只用系统自带的解释器与标准库。
5. **保存**：调用 `save_skill(name, description, instructions, files)`。用户会看到确认卡片，被拒绝就停下、按用户意见改，不要换个名字重试。
6. **告诉用户怎么用**：一句话说明以后输入 `/技能名 需求` 即可调用，并给一个调用示例。

## 修改已有技能

用户要改某个自己的技能时：先 `read_file` 读技能库里 `<技能名>/SKILL.md`（路径见系统提示的技能库目录）看现有内容，在它基础上改，再用**同一个 name** 调 `save_skill` 覆盖。内置技能和从 GitHub 安装的技能不能被覆盖——要改的话换个名字另存一份。

## 安装别人写好的技能

用户想用开源技能时，告诉他在输入框里发 `/skills add <owner/repo>`（可加 `--skill <名字>` 只装其中一个），写法与 `npx skills add` 一致；也可以在「技能」页粘贴同样的命令或 GitHub 链接安装。
