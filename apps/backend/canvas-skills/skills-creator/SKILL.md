# skills-creator · 给画布智能体写技能

技能是一份**可复用的工作流说明书**（SKILL.md）。保存后，用户在对话里输入 `/技能名` 就能让你照着它做；任务与技能说明相符时，你也会自己读它来用。
画布上最常见的技能是**视频工作流**：怎样从一句需求出发，拆分镜、写提示词、搭节点、连参考图、出图出片、拼成一条成片。

## 你在写给谁看

技能的读者是**将来的你自己**——同一个画布智能体，拿到的工具与限制完全一样。所以：

- 只能写画布智能体**真的做得到**的步骤。动手前先读 `/skills/skills-creator/references/canvas-capabilities.md`，那里列了全部工具、节点类型、连线规则与限制。
- 不能写做不到的事：例如「把视频比例设成 9:16」「选 Veo 模型」——你的工具改不了节点的模型和档位（那是用户在节点面板里选的）。需要特定比例/时长时，写成「在提示词里描述构图」并「提醒用户在节点面板里设置」。

## 流程

1. **弄清目标**（缺什么问什么，一次问完，用 `ask_user`；用户已经说清楚的不要再问）：
   - 这个技能解决什么任务？用户以后会怎么说出这个需求（触发说法）？
   - 每次运行需要用户提供哪些输入（主题、产品、风格、镜头数、参考图…）？哪些可以有默认值？
   - 成片长什么样：几个镜头、每镜大约几秒、叙事结构、统一的视觉风格。
   - 如果用户是想把**本次对话里刚做过的流程**存成技能，直接从对话和画布里提炼，少问。
2. **起名与写说明**：
   - `name`：小写字母、数字、连字符，≤64 字符，例如 `product-teaser-video`。不能叫 `skills-creator`（内置技能不能覆盖）。
   - `description`：一段话写清**做什么 + 什么时候用**，把用户可能的说法写进去（它决定你以后能不能认出该用这个技能）。≤1024 字符。
3. **写正文**（Markdown，不含 frontmatter，save_skill 会替你加上）。结构参考 `/skills/skills-creator/references/video-workflow-example.md`，至少包含：
   - **输入**：要向用户收集什么、缺了怎么补默认值。
   - **步骤**：按顺序写清每一步用哪个工具做什么，节点怎么布局、怎么连线、何时触发生成。
   - **提示词写法**：每类节点的提示词模板（主体、动作、镜头、光线、风格、时长感），以及如何保持跨镜头一致（同一角色/产品的描述原样复用、用上游关键帧图作参考）。
   - **检查清单**：交付前要核对的点。
4. **保存**：调用 `save_skill(name, description, instructions)`。审批模式下用户会看到确认卡片，被拒绝就停下、按用户意见改，不要换个名字重试。
5. **告诉用户怎么用**：一句话说明以后输入 `/技能名 + 需求` 即可调用，并给一个调用示例。

## 修改已有技能

用户要改某个自己的技能时：先 `read_file /skills/<技能名>/SKILL.md` 看现有内容，在它基础上改，再用**同一个 name** 调 `save_skill` 覆盖。内置技能不能被覆盖或删除。

## 写得好的技能长什么样

- 步骤是**可执行的**：读的人照着做就能在画布上搭出来，不需要再猜。
- 提示词模板具体（"9 秒、缓慢推近、侧逆光、浅景深"），而不是空泛（"高质量、好看"）。
- 不重复画布智能体已经知道的通用规则（怎么调工具、要写计划等），只写这个任务特有的做法。
- 篇幅够用就好，通常 60–200 行。
