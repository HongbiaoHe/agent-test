# 画布智能体能力清单（写技能前必读）

写进技能的每一步都必须落在下面这些能力之内。

## 节点类型

| 类型 | 作用 | 输入（入边） | 输出 |
| --- | --- | --- | --- |
| `image_gen` | 生图。提示词写在节点自己的 `prompt` 上 | 上游图片作参考图（可多张，按连线顺序编号为 Image 1/2…） | 图片 |
| `video_gen` | 生视频。提示词写在节点自己的 `prompt` 上 | 上游图片 / 视频 / 音频作参考素材（图生视频、视频续写、按配乐生成） | 视频 |
| `video_concat` | 把多段上游视频按**入边顺序**拼成一条（本地拼接，不调模型） | 只接视频，至少 2 段；拼接产物也能再连给下一个拼接或 video_gen | 视频 |
| `image_upload` / `video_upload` / `audio_upload` | 用户上传的图片 / 视频 / 音频 | 无输入端口 | 图片 / 视频 / 音频，可作为下游的参考素材 |

- 连线 A → B 表示 A 是 B 的上游输入，只传递**参考素材**；提示词不走连线。
- 每类素材能参考几个由节点所选模型决定（模型目录里的图片 / 视频 / 音频数量上限），超出的不提交；首帧模式的视频模型只取第一张图。
- 上传节点的文件只能来自用户：用户在对话里发的附件会以「[附件]」清单出现（类型 + versionId + 文件名），用 `add_node` 建同类型的上传节点并传 `versionId` 摆上画布；不传 versionId 的上传节点是空的，要等用户自己在卡片上传。

## 工具

| 工具 | 用途 | 要点 |
| --- | --- | --- |
| `write_todos` | 把任务拆成有序计划并逐项推进 | 一次运行内做完全部步骤 |
| `list_media_models(type)` | 查可用的生图 / 生视频模型 | 返回每个模型的可选档位（画幅、清晰度、时长、音频等）、参考素材数量上限、约束规则和用途提示；目录会变，以它的返回为准 |
| `add_node(type, label?, prompt?, model?, channel?, params?, versionId?, x?, y?)` | 新建节点 | 生成节点建时就带上 prompt、`model`、`params`（如 `{ aspect_ratio: "16:9", duration: "5" }`），不传就是默认模型的默认档位；参数不合法会返回 issues 且不建节点。上传节点用 `versionId` 挂用户附件。位置放进「放置安全区」 |
| `update_node(nodeId, label?, prompt?, x?, y?)` | 改标题 / 提示词 / 位置 | 改模型和档位用 `set_node_model` |
| `set_node_model(nodeId, model?, channel?, params?)` | 给已有生成节点换模型或改档位 | 不传 model 表示只改档位；params 只传要指定的维度；不合法返回 issues（含可选值） |
| `connect_nodes(sourceId, targetId)` | 连线 | 遵守上表的输入 / 输出类型；上传节点不能作为连线终点 |
| `delete_node(nodeId)` | 删除单个节点 | 搭错优先 update_node 修，不要删了重建 |
| `clear_canvas()` | 清空整块画布 | 会请用户确认 |
| `generate_media_node(nodeId)` | 触发 image_gen / video_gen 生成（异步） | 先写好 prompt；审批模式下会请用户确认；触发后立即返回 queued，不要轮询或重复触发 |
| `merge_video_node(nodeId, order?)` | 触发 video_concat 拼接（异步） | 上游视频在生成中也能触发，会等它们完成再拼；`order` 可按叙事顺序列出上游节点 id，先重排再拼；返回实际拼接顺序 |
| `set_clip_order(nodeId, order)` | 调整拼接顺序（= 成片顺序） | 只改顺序不拼；已拼好的要再调 merge_video_node 重拼 |
| `ask_user(question, options?)` | 向用户提问并等待回答 | 只问关键选择 |
| `read_file(path)` | 读文件 | 读技能：`/skills/<名>/SKILL.md` |
| `save_skill(name, description, instructions)` | 保存 / 覆盖用户技能 | 只在创建或修改技能时用 |

画布当前状态（全部节点、连线、短 id、放置安全区）会自动出现在对话里，不需要工具去查。节点行末会标出 `<生成:queued|generating|done|failed|cancelled>` 和显式设过的 `<模型:…>`。

## 触发顺序：一步全部触发

- 下游可以在上游还在排队 / 生成时触发：它会带上上游这次的版本，等上游出结果再开始。
- **同一步里一起调用**的 `generate_media_node` / `merge_video_node` 会自动按连线依赖排好顺序。所以整条工作流（关键帧 → 视频 → 拼接 → 再拼接）搭好之后，在同一步里把所有要触发的节点一次调用完即可，不需要分几轮、也不需要等用户说「继续」。
- 上游必须在同一步里一起触发，或之前已经触发过；连着却既没产物也没触发的上游（包括空的上传节点、失败的节点）会让下游报错并点名该上游。

## 限制（技能里不能承诺的事）

- 不能自己上传或读取用户本地文件、不能联网搜索、不能运行代码；上传素材只能来自用户发的附件或用户在卡片上传。
- 转场、字幕、配乐混音不在能力之内：只能通过提示词影响画面内容，用 `video_concat` 按顺序硬切拼接；音频只能作为 video_gen 的参考素材。
- 模型和档位只能从 `list_media_models` 返回的目录里选；目录会增减模型，技能里不要写死某个具体模型，写清需要的规格（画幅、时长、要不要收视频 / 音频参考），运行时按目录选能满足的模型。

## 常见视频工作流骨架

1. 关键帧：每个镜头一个 `image_gen`，写好画面提示词（主体 + 场景 + 构图 + 光线 + 风格）；需要统一角色 / 产品时，先做一张设定图，再让各镜头关键帧以它为参考（图生图）。
2. 动起来：每个镜头一个 `video_gen`，从对应关键帧连一条线作参考图，提示词写动作、运镜、节奏与时长感。
3. 续写：需要延续上一段动作时，再加一个 `video_gen`，以上一段视频为参考（模型要支持视频参考）。
4. 成片：一个 `video_concat`，把各镜头视频按叙事顺序依次连进来（入边顺序 = 成片顺序，画布状态里标为 `<拼接顺序: …>`）；触发前核对顺序，不对就给 merge_video_node 传 `order`。分段拼好的片段还可以再连进总拼接。
5. 模型与档位：建生成节点时用 `model` / `params` 一次定好，同一条片子里各镜头的画幅与清晰度保持一致。
6. 触发：结构全部搭好后，在同一步里一次触发所有生成和拼接节点。
7. 布局：从左到右按依赖层级排开（关键帧 → 视频 → 拼接），同一层纵向错开；竖版画幅的卡片更高，纵向间距要留够。
